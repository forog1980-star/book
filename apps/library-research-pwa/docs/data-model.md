# مدل داده نسخه ۰٫۱

| موجودیت | شناسه پیشنهادی در برنامه | هدف |
|---|---|---|
| کتاب‌شناختی | `BK-<UUID>` | توصیف اثر، عنوان خام، پدیدآورنده، ناشر، سال، دسته، شاهد مشخصات کتاب، منشأ و وضعیت بررسی |
| نسخه فیزیکی | `CP-<UUID>` | هر جلد واقعی، محل، مشاهده، وضعیت ظاهری و تاریخچه جابه‌جایی |
| شهید | `MT-<UUID>` | پرونده هویتی با نام خام، نام جایگزین، شاهد/منبع هویت و اجزای متنی نشانی مزار |
| ارتباط کتاب–شهید | `LNK-<UUID>` | رابطه چندبه‌چند با نوع ارتباط، شرح، ارجاع شاهد/صفحه، منشأ و وضعیت بررسی |
| مطلب استخراج‌شده | `EXT-<UUID>` | خلاصه، یادداشت، نوع مطلب، شماره صفحه خام، شهید مرتبط و وضعیت بررسی/بازبین |
| بسته ورود | `IMP-<UUID>` | نام فایل، اندازه، SHA-256، شیت، ردیف سرستون، نگاشت و شمارش‌ها |
| ردیف خام منبع | `<batchId>-<rowNumber>` | مقادیر سلول‌ها، فرمول‌ها، ردیف مبدأ و شناسه بسته ورود |
| رویداد ممیزی | `AUD-<UUID>` | نوع موجودیت، عمل، کاربر محلی، زمان و شرح تغییر |

## قواعد کلیدی

- هر اثر می‌تواند صفر یا چند نسخه فیزیکی داشته باشد.
- یک کتاب می‌تواند با چند شهید و یک شهید با چند کتاب مرتبط باشد.
- شباهت عنوان/نام فقط برای پیشنهاد بررسی است؛ هیچ ادغامی خودکار نیست.
- `sectionRaw`, `graveRowRaw` و `graveNumberRaw` به‌صورت رشته نگهداری می‌شوند تا صفر ابتدایی و حروف از دست نروند.
- `pageReferenceRaw` به‌صورت متن حفظ می‌شود و بازه صفحه به عدد تبدیل نمی‌شود.
- `identityEvidenceRaw` برای ثبت پرونده شهید اجباری است؛ نام مشابه به‌تنهایی شاهد هویت نیست.
- `sourceEvidenceRaw` برای ثبت دستی کتاب اجباری است؛ نمونه آن جلد، صفحه شناسنامه یا مرجع کتاب‌شناختی است. منشأ فایل Excel برای داده واردشده خام، جداگانه در `SourceRef`/بسته ورود ثبت می‌شود.
- `evidenceReferenceRaw` برای ایجاد ارتباط کتاب–شهید اجباری است؛ ارتباط تازه همیشه `proposed` می‌ماند تا بازبین تصمیم بگیرد.
- `reviewNote`, `reviewedAt` و `reviewedBy` در ارتباط‌ها و مطالب پژوهشی برای نگهداری نتیجه بررسی جدا از یادداشت ثبت‌کننده استفاده می‌شوند.
- مقادیر خام و مقادیر نرمال‌شده جست‌وجو از هم جدا هستند.
- وضعیت انتشار رکوردهای ایجادشده در این نسخه `blocked` است.
- منشأ Excel با `fileName`, `sheetName`, `rowNumber`, `sourceSha256` و `fieldMapping` ثبت می‌شود.

## وضعیت بررسی

کتاب و نسخه فیزیکی در ثبت اولیه `needs_review` هستند. رابطه کتاب–شهید `proposed` و مطلب پژوهشی `draft` است. تغییر وضعیت فقط از مسیر بازبینی انسانی در نرم‌افزار انجام می‌شود. تأیید پژوهشی به‌تنهایی مجوز انتشار ایجاد نمی‌کند.
